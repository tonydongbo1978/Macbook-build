# 第 5 章：Agentic Workflow 的设计与实现

## 核心思想
单个 Agent 只能处理孤立任务；真实业务是**多步骤、有依赖、会出错**的。Agentic Workflow 用"结构化流程 + 自主决策"解决这个落差：流程给可控性，Agent 给适应性。**它替代的不是人，而是"写死的流程图"。**

## 本章框架

- **与传统工作流的区别**：规则驱动 vs 目标驱动；固定路径 vs 动态路径；执行 vs 决策；无记忆 vs 有状态；不可学习 vs 可反馈优化。
- **七大特征**：自主性、协作性、目标导向与规划、工具使用与行动、状态感知与适应性、结构化流程、反馈与学习潜力。
- **八项功能**：任务规划分解、工具调用集成、自主推理决策、记忆管理、反思优化、多 Agent 协作、动态路径规划、人类交互监督。
- **六种工作模式**：链式、并行化、路由、反思与迭代、工具调用、多 Agent 协作（实际系统多为组合）。
- **七类工作流**：单 Agent、多 Agent 协作、Agentic RAG、迭代优化、动态决策、人类交互、混合。
- **7 个核心组件**：执行引擎（编排层）、推理模块、记忆模块、工具集、提示词模板库、可观测性存储、人在回路。
- **四大设计模式（吴恩达框架）**：
  1. **规划**：分解任务、生成计划、动态调整；
  2. **工具使用**：调 API/数据库/代码解释器扩展能力；
  3. **反思**：自评输出、识别错误、迭代改进；
  4. **多 Agent 协作**：分工 + 通信 + 任务一致性。
  - 衍生模式：自适应、记忆管理、任务协调、并行处理。
- **构建 8 步**：定参数 → 选平台/框架 → 设计工作流 → 选模型并设计提示 → 集成工具与数据 → 端到端测试 → 部署（试点/灰度/全量）→ 监控优化。
- **12 条最佳实践**：KISS、模块化可复用、指令清晰、工具描述规范、状态可恢复、错误处理与容错、全面测试（单元/集成/E2E/性能）、可观测性、安全（沙箱/最小权限）、成本控制、人在回路、文档化。
- **该不该上 Agent 的四问（作者给的判断器）**：
  1. 任务复杂到需要适应性决策，还是确定性方法就够？
  2. 更简单的 AI（如纯 RAG）能否达到同样结果？
  3. 是否存在不确定性、条件变化、多步推理？
  4. 授予自主性的风险能否被缓解？

## 关键概念
- **结构化流程**：即使是自主 Workflow，也要有预定义结构（图/链/层级/状态机）以保证可调试。
- **人在回路（HITL）**：在关键节点插入审批，兼顾自主与可控。
- **可观测性存储**：记录决策轨迹、工具调用、指标，是排障与审计的基础。
- **Agentic RAG**：检索也交给 Agent 规划（分解查询、多源检索、反思补检）。

## 心智模型
- **"流程是骨架，Agent 是肌肉"**：没有骨架的自主会失控，没有肌肉的骨架是 RPA。
- **"简单任务上 Agent 是负优化"**：表单填写、固定提取用规则更快更便宜。
- **"自主性越高，可观测性要求越高"**：两者必须同比例增长，否则不可运维。

## 反模式
- 用 Agent 重做本可用确定性规则完成的流程（成本升、稳定性降）。
- 只做单 Agent、不做编排，遇到跨系统任务就卡住。
- 没有状态持久化：长流程中断即从头再来。
- 把"多 Agent"当卖点，实际是 5 个 Agent 互相等待。

## 关键结论
1. 选模式的依据是"任务确定性 × 质量要求 × 协作需求"，不是技术潮流。
2. 反思模式对质量提升最明显，但会成倍增加 token 成本——要设迭代上限。
3. 上 Agent 前先做"四问"筛查，能把一半不该做的项目挡在门外。
