# 第 3 章：技术实现

## 核心思想
Agentic AI 的工程本质是**"感知—推理—行动—学习"的闭环系统**：LLM 当大脑（推理引擎/工具选择器/响应合成器），工具当手脚，记忆当上下文，编排层当神经系统。它不是一个模型，而是一套把模型能力"接进现实世界"的架构。

## 本章框架

- **运行循环（7 步）**：自然语言输入 → 意图理解与澄清 → 解释与工作流生成（任务分解、分配给子 Agent）→ 工作流执行 → 工具调用 → 输出/学习/纠偏 → 反馈回流（数据飞轮）。
- **LLM 的三大跃迁**：
  1. **推理引擎**：把抽象目标拆成可执行步骤链（"分析财务趋势"→取财报→清洗→可视化→解读）；
  2. **工具选择器**：建立"需求—工具"语义映射（查数→搜索 API，算数→Python）；
  3. **响应合成器**：把碎片结果整合成结构化输出。
- **五个核心组件（作者采用的分法）**：感知 → 认知 → **记忆** → 行动 → 学习。
  - 记忆单列的原因：它是"跨轮次一致性"与"经验复用"的唯一载体。
- **六层技术架构**：协调与控制层（编排）→ 感知层 → 推理与规划层 → 记忆层 → 执行层 → 输出层。
  - 编排层位置有两种设计：前置（总体控制）或后置（结果监管），取决于治理需求。
- **技术栈两层视角**：
  - 基础栈：应用层 / 模型层（LLM+框架）/ 基础设施层（云、向量库、编排、API）；
  - **企业级栈（Agentic AI Stack）**：触达层（界面、第三方 Agent、B2A）/ 能力层（控制、编排、智能、工具）/ 数据层（记录系统、Agent 员工会计）。
  - 该框架的判断：**Agentic AI 的成功 20% 靠技术，80% 靠变革管理**。
- **构建 Agent 的 8 步**：明确目标与边界 → 选核心 LLM → 设计工具（原子性、清晰接口、健壮错误处理）→ 设计提示（角色/目标/工具清单/ReAct 指令/约束/输出格式）→ 构建执行循环 → 实现记忆（上下文窗口 + 向量库 + RAG）→ 用框架简化（LangChain/LangGraph/AutoGen/crewAI/LlamaIndex）→ 测试迭代与安全。

## 关键概念
- **Function Calling / Tool Calling**："模型决策—工具执行—结果回流"的闭环机制。
- **Agentic RAG**：把检索从"一次性查"变成"分解查询—多轮检索—反思修正"。
- **护栏（Guardrail）**：如客服 Agent 的赔付金额上限，超限转人工。
- **数据飞轮**：交互数据回流训练/检索库，形成越用越准的正循环。

## 心智模型
- **"架构比模型重要"**：同一模型，编排与工具设计不同，任务成功率可以差数倍。
- **"工具即能力边界"**：Agent 能做多少事，取决于你给它接了多少可靠工具，而不是它多聪明。
- **"记忆是产品，不是缓存"**：记忆结构（情景/语义/短期/长期）决定它能否"越用越懂你"。

## 反模式
- 只接一个模型、不接工具，然后期待"自主完成任务"。
- 把所有上下文塞进提示词，不做检索与摘要（成本爆炸且效果下降）。
- 工具描述含糊（"查数据"而非"按订单号查物流状态，返回 JSON"），导致调用失败。
- 没有护栏就放开写操作（赔付、退款、发邮件）。

## 关键结论
1. 判断一个 Agent 系统成熟度，看它**工具集质量**与**失败恢复路径**，而非 demo 效果。
2. 企业级落地的主要工作量在集成与治理（80%），不在模型调优（20%）。
3. 记忆与工具是"可积累资产"，模型是可替换部件——架构上要把它们解耦。
