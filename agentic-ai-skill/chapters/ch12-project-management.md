# 第 12 章：项目管理与优化

## 核心思想
Agentic AI 项目的管理难点在于：**交付物是概率性的**。传统项目管理假设"需求确定、验收明确"，而 Agent 的行为随上下文漂移。因此治理要从"管任务"升级为"管边界 + 管度量 + 管可观测性"。

## 本章框架

- **治理九原则**：战略对齐、价值驱动、风险可控、责任明确、透明公开、伦理优先、合规守法、持续学习与适应、以人为本。
- **治理结构与角色**：指导委员会（高管+业务/IT/法务+伦理专家）、PMO/CoE（标准与复用）、项目发起人、业务/产品负责人、项目经理、技术负责人/架构师、数据治理代表、AI 伦理审查小组。
- **八项治理机制**：立项筛选 → 阶段性审查（需求/原型/测试/部署前闸门）→ 风险管理（识别/评估/应对/监控）→ 变更管理 → 数据治理 → 合规与伦理审查 → 效能度量 → 知识管理（复盘入库）。
- **持续优化机制**：指标定义 → 数据采集（日志/评分/反馈）→ 归因分析 → 迭代（提示/工具/模型/流程）→ 再验证；核心是"把优化当成常规运营动作"。
- **人机协作的八类管理挑战**：信任不足、职责边界模糊、沟通方式差异、技能缺口、流程未同步重塑、偏见与伦理输出、自主与控制的平衡、替代焦虑与文化阻力。
  - 十条对策：透明与可解释、明确角色与授权、设计交互协议、赋能培训、迭代流程、伦理审查与偏见缓解、HITL/HOTL 分级、协作文化、持续学习、试点先行。
- **三个项目管理实践案例**：
  - **Moveworks**：Agentic Automation Engine（自然语言→结构化 API 调用）、多 Agent 架构、100+ 预构建插件市场；某市政府 IT 帮助台每年省 3000+ 小时；**经验：统一协调机制 + 日志驱动优化**。
  - **Accenture（AI Refinery）**：12 个行业 Agent 方案、无代码构建器、多 Agent 协作；项目交付速度 +30%，跨系统任务 1 小时内完成；**经验：冲突处理机制、可观测性（无日志=无治理）**。
  - **Lattice**：HR 场景的 AI 协作平台，从被动响应转主动支持。

## 关键概念
- **可观测性（Observability）**：日志 + 追踪 + 指标三件套；"无日志 = 无治理"是本章最有用的判断。
- **冲突处理机制**：多 Agent 给出矛盾建议时的仲裁规则（优先级/置信度/人工裁决）。
- **效能度量**：不只看项目进度，还看 Agent 的任务成功率、接管率、单任务成本。

## 心智模型
- **"管边界，不管步数"**：不要去规定 Agent 每一步怎么做，而是定义它能做什么、不能做什么、出界怎么办。
- **"验收标准要写成分布"**：不是"能回答"，而是"1000 个样本里 ≥95% 正确且 <2% 需接管"。
- **"复盘入库"**：每个项目的失败模式要变成组织的护栏与测试用例。

## 反模式
- 用瀑布式需求文档管理概率系统（需求一改，验收全废）。
- 只在上线前测一次，不做持续回归（模型/工具/数据任一变化都会漂移）。
- 把"人工接管"当失败（它其实是安全阀，关键是接管率要可度量、可下降）。

## 关键结论
1. Agentic 项目的治理重心从"进度"转向"边界 + 度量 + 可观测"。
2. 多 Agent 系统必须有仲裁机制，否则"协作"会变成"互相甩锅"。
3. 持续优化的前提是日志完整；没有日志，所有"优化"都是猜测。
