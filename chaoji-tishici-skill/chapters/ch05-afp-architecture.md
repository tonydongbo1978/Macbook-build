# 第 5 章：AFP 架构——构建微型操作系统

## 核心思想
AFP（Auto-Flow Prompt）把提示词从"一段文字"变成"一套可运行的系统"，由四个要素构成：**程序化运行、任务工作流化、角色赋能、全景仪表盘**。它的本质是把"控制权"从人手里交给流程。

## 本章框架

- **要素一：程序化运行（Push → Pull）**
  - Push 模式（传统）：人推着 AI 走，每步都要人下指令——逻辑倒灌、管理冗余、交互惯性。
  - Pull 模式（AFP）：AI 持流程，主动"拉取"变量、在关键节点请求确认。
    - 三个变化：命题作文→选择题；苏格拉底追问→专家外挂；碰运气→工业标准（质量稳定在 80 分以上）。
  - 实现：**运行时协议**（严格步进：禁止一次性输出；后台静默：思考不外显；心跳信号：状态码）。
- **要素二：任务工作流化（SOP）**
  - 从"文档级 SOP（软约束）"到"产品级 SOP（硬约束）"：`Step + [STOP]` 强制停点。
  - 与普通提示词的三点差异：控制颗粒度（硬约束 vs 弱引导）、交付形态（阶段性中间件 vs 最终件）、质检机制（内置审计角色 vs 事后人工检查）。
  - **五段式工作流**：Diagnosis（收输入+画像确认）→ Context Injection（补数据/口径）→ Blueprint（结构+优先级确认）→ Execution Loop（逐条生成+逐条审计+逐条验收）→ Packaging（排版+增值资产）。
  - 作者提醒：真实任务是"工作网"而非流水线，SOP 只是把网降维成可执行结构。
- **要素三：角色赋能（单核 → 多核）**
  - 单核的病：答案平庸（取"平均解"）、谄媚用户（取悦是低风险策略）。
  - **双对抗模式**：A 执行、B 审计；B 只挑错不夸奖。
    - **独立性约束**（关键）：禁止赞美、默认不通过、惩罚性措辞——否则两角色会互吹。
  - **多角色赋能**：按环节分工（策略官/文案官/证据官/红队审计/发布经理），各有权重与交付物。
  - **自进化角色**："提示词进化官"把用户反馈转成提示词层面的可执行改动。
- **要素四：全景仪表盘（HUD）**
  - 原理：对抗长对话中的"指令稀释"——每轮强制重写状态（阶段/交付物/把关/下一步），形成"语义快照"。
  - 收益：持久化记忆、纠错锚点、体验可控。
  - 规范三字：**简**（只留 Phase/Deliverable/PASS/NEXT）、**尾**（放在回复末尾，兼作总结与导航）、**少**（一个主仪表盘为主，必要时按功能分屏）。
- **AFP 决策矩阵**（是否该用 AFP）：
  | 认知负载 | 结构化要求 | 象限 | 结论 |
  |---|---|---|---|
  | 高 | 高 | 统治区 | 最适用 AFP |
  | 高 | 低 | 开放区 | 用"创意版"AFP（减约束） |
  | 低 | 高 | 自动区 | 用"轻量版"AFP（省事+一致） |
  | 低 | 低 | 禁止区 | 别用（纯负收益） |

## 关键概念
- **Pull 交互**：AI 主动拉取信息与确认。
- **[STOP]**：强制停点，交互权翻转的锚。
- **独立性约束**：防止审计角色被同化。
- **语义快照**：每轮重写状态以对抗注意力稀释。

## 心智模型
- **"把人从'推车'变成'选路'"**：人只做判断，流程由系统持。
- **"没有对抗，就没有质量"**：单角色必然滑向平均解。
- **"仪表盘是给模型的，不是给人的"**：它的功能是锚定注意力。

## 反模式
- 只加角色不加独立性约束（两角色互吹）。
- 仪表盘堆满指标（噪声反而稀释锚点）。
- 简单任务硬上 AFP（流程成本高于收益）。

## 关键结论
1. AFP 的四个要素是一条链：Pull 定节奏 → SOP 定路径 → 角色定质量 → 仪表盘定稳定。
2. 质量控制的关键是"制度化的对抗"，不是"更聪明的模型"。
3. 先判断象限，再决定要不要 AFP——这是最高杠杆的一步。
