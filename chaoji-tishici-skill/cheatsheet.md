# 速查表：写提示词的决策规则

## 决策规则（当 X，做 Y，因为 Z）

| 当… | 做… | 因为… |
|---|---|---|
| 同类任务会反复做 | 做成场景型提示词 | 任务型是日抛消耗品（ch02） |
| 提示词换个主体就报废 | 把内容抽成变量，结构留下 | 资产=结构与内容解耦（ch02） |
| 输出"专业但空洞" | 补常量（行业标准）与算法（判断逻辑） | 只写变量＝没受过训练的人在模仿（ch04） |
| 想表达"幽默/高级/有网感" | 拆成可执行机制 + 禁区 + 判据 | 形容词是愿望，不是算法（ch04） |
| 有明确阈值/对错 | 写 If-Then 分支 + 依据 | 不写分支，模型只能猜（ch04） |
| 任务简单、一次性 | 别上 AFP，用短提示词 | 流程成本高于收益（ch05） |
| 多轮任务总在"人推一步" | 改 Pull：严格步进 + [STOP] 索取 | 交互权该交给流程（ch05） |
| 交付错误代价高 | 加双核审计 + 独立性约束 | 单核必然输出平均解（ch05） |
| 长链路开始漂移 | 每轮输出极简仪表盘 | 对抗指令稀释（ch05） |
| 不知道 AFP 要不要上 | 先放"认知负载 × 结构化要求"矩阵 | 四象限结论不同（ch05） |
| 从零构建复杂提示词 | 走四步法，先粗后细 | 一上来写细节必然跑偏（ch06） |
| 要对外发布提示词 | 三明治防御 + 不写秘密 | 防御只抬高成本（ch09） |
| 已有可用 AFP | 拆常量→封装 Skill | 获得分发与版本能力（ch10） |

## 阈值与数字（书中锚点）

- **成本**：三年推理成本降约 99%（旗舰接近 99.75%）（ch01）。
- **上下文**：100 万–200 万 token（约一部《红楼梦》/10 本专业书）（ch01）。
- **结构占比**：1.0 时代 10% 结构 → 5.0 时代 80% 结构（ch02）。
- **算法四要素**：步骤骨架 / 分支规则 / 判断锚点 / 容错收口（ch04）。
- **工作流五段**：Diagnosis / Context Injection / Blueprint / Execution Loop / Packaging（ch05）。
- **估值**：Value = (Expertise × Structure) × Frequency，任一为零则总为零（ch09）。
- **变现四路**：知识付费 / 企业合同 / 工程化产品 / 自动化内容生产（ch09）。

## 识别信号（出现这些，说明写坏了）

- 满篇"专业、高级、有感染力" → 没有颗粒度（ch04）。
- 只有 Step1..N，没有分支与例外 → 一遇变体就崩（ch04）。
- 角色只有一个人 → 必然平庸 + 谄媚（ch05）。
- 审计角色开始夸执行角色 → 缺独立性约束（ch05）。
- 仪表盘列了十几项 → 噪声稀释锚点（ch05）。
- 提示词里写着 API Key / 内部数据 → 资产变负债（ch09）。
- 简单任务用了 AFP → 纯负收益（ch05）。

## 一句话判据

> **提示词的价值 = 你注入了多少不可替代的判断 × 结构能让它稳定多久 × 这个场景多久发生一次。**
