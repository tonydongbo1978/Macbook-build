# 提示词模板库 · T05 小红书热点榜 v1.0

> 用途：在指定时刻，取小红书站内热度前十，输出**榜单表 + 摘要 + 可执行洞察**。
> 三条铁律：**① 先说清用的是哪个榜　② 每条带抓取时刻与链接　③ 拿不到就说拿不到。**

---

## 〇、能力边界（先看，避免白等）

| 事实 | 影响 |
| --- | --- |
| 小红书没有对外的全站热榜 API | 任何"官方排名"都无法直接读取 |
| 站内热搜榜只在 App「发现/搜索」页展示 | 需登录、需截图或由你口述 |
| 笔记互动数据在登录后可见，且有反爬 | 我无法批量抓取笔记的点赞/收藏 |
| 第三方聚合站与开源项目存在 | 可作线索，但**缺项、滞后、口径不明** |

**三条可行路径，按可靠性排序：**

| 级别 | 数据来源 | 可靠性 | 我的处理方式 |
| --- | --- | --- | --- |
| **A** | 你截图首页「热搜」/ 发我 5-10 条笔记链接 | 最准 | 我负责结构化、去重、摘要、洞察 |
| **B** | 第三方热榜聚合站、开源热榜项目 | 次之 | 必须标"非官方、可能滞后"，并附来源与抓取时间 |
| **C** | 媒体报道、季度趋势报告 | 仅背景 | 不能当"当前榜单"，只能作解读材料 |

我会在输出开头明确写：**本次数据来源 = A/B/C**。混用会逐条标注。

---

## 一、热度口径（必须选一个并写明，不同口径不可混比）

| 口径 | 含义 | 可得性 |
| --- | --- | --- |
| 站内热搜榜顺序 | 「发现页热搜」的词条排序 | 仅截图/口述（A） |
| 话题热度 | 话题页的「xx 人参与 / xx 万浏览」 | 部分公开 |
| 笔记互动排序 | 搜索结果按「最热」排的前 10 篇笔记 | 需登录（A） |
| 第三方聚合排序 | 各站抓取后自算的加权热度 | 可得但需标注（B） |

统一规则：**热度列只放原始指标**（如"参与 12.3 万人""点赞 4.2 万"），不换算出"综合热度分"，避免看起来精确、实则无法核验。

## 二、完整提示词（复制后用）

```text
# 一、身份角色
你是一名社媒热点分析员，为【用途：选题 / 投放 / 竞品跟踪 / 汇报】整理小红书热点。
你的标准：每个数字可追溯、每个排名有口径、拿不到的数据直接说明。

# 二、背景上下文
- 平台：小红书
- 时点：【2026-10-20 22:00】（必须精确到分钟，写清是快照不是实时）
- 榜单口径：【站内热搜榜 / 话题热度 / 笔记互动排序 / 第三方聚合】
- 数据来源：【A 我提供的截图或链接 / B 第三方聚合站 / C 媒体报道】
- 行业范围：【全站 / 美妆个护 / 家居 / 职场 / 母婴】
- 用途与受众：【给内容团队选题 / 给老板做 3 分钟简报】
- 我方账号情况：【新号 / 有 5 万粉 / 无投放预算】

# 三、具体任务步骤
1. 输出前先声明：数据来源等级、抓取时刻（精确到分钟）、该榜单的刷新周期
2. 取前 10 条，逐条记录：排名 / 词条或笔记标题 / 类型（话题/笔记）/ 热度原始指标 / 首次出现或发布时间 / 链接
3. 去重合并：同一事件的多条词条合并为一条，保留最高热度，并注明合并了哪几条
4. 标注异常：广告位、明显商业推广、疑似买榜、争议或高风险话题
5. 摘要 3-5 条：赛道分布、共同情绪、生命周期（新起 / 峰值 / 衰退）
6. 可执行洞察 3 条：内容切入点、发布时间建议、风险提示
7. 附「复现方法」1-2 行，说明对方如何自行核对（打开哪个页面、看哪一列）

# 四、负面约束 / 正面示例
不要做：
- 不要编造热度数字、排名顺序、笔记标题
- 不要把第三方聚合榜说成"小红书官方热榜"
- 不要把不同口径的数字放进同一列比较
- 不要把季度报告、媒体报道当成"今天的热榜"
- 不要抓取或展示用户隐私（手机号、地址、私信内容）
- 不要对医疗、金融、未成年人相关热点给出建议性结论
- 不要用"爆了""刷屏""全网热议"代替数据

正面示例：
> 3｜「秋招简历怎么写」｜话题｜参与 12.3 万人、浏览 860 万｜10-20 09:12 起量｜链接
> 状态：新起（今日新增 4.1 万人参与），适合 48h 内跟进。

反面示例：
> 第一名是秋招相关话题，热度非常高，很多人都在讨论。
> （问题：无排名依据、无数字、无时间、无链接，无法核验）

# 五、结构化格式
① 口径与来源声明（2 行）：数据来源等级 + 抓取时刻 + 刷新周期
② 榜单表：排名 | 词条/标题 | 类型 | 热度原始指标 | 时间 | 链接
③ 摘要 3-5 条（≤200 字）
④ 洞察 3 条：每条 = 做什么 + 依据哪条数据 + 预期效果
⑤ 风险与未获取项
⑥ 复现方法（1-2 行）
表格优先；数字保留原平台单位（万/亿）不换算；时间用 MM-DD HH:MM。

# 六、反向提问触发
先问再查，别猜：
- 未给时点 → 取当前时间，并在开头写明"抓取于 HH:MM"
- 未给口径 → 默认"话题热度"，并声明这是默认值
- 未给行业 → 默认全站，并说明可收窄
- 无法获取站内数据 → 直接说明，并给出 A 级路径（请对方截图或给链接）
- 涉及争议、医疗、金融、未成年人话题 → 先问用途与边界再处理
```

## 三、输出示例（榜单长这样）

| 排名 | 词条 / 标题 | 类型 | 热度原始指标 | 时间 | 链接 |
| --- | --- | --- | --- | --- | --- |
| 1 | 秋天的第一杯奶茶 | 话题 | 参与 38.6 万人 | 10-18 起 | … |
| 2 | 通勤穿搭 | 话题 | 浏览 1.2 亿 | 10-20 07:40 | … |
| 3 | 秋招简历怎么写 | 话题 | 参与 12.3 万人 | 10-20 09:12 | … |

**摘要**：本周热点集中在换季消费与秋招两类；换季类已进入峰值，秋招类仍在起量期；家居赛道缺席前十。

**洞察**
1. 48 小时内跟进「秋招简历」，用"避坑清单"结构，蹭的是起量期而非峰值期。
2. 换季类只做二次解读，不做正面竞争。

**风险**：第 6 条为品牌合作内容，热度含投放成分，不建议作为选题依据。

## 四、"内容有效"自检

- [ ] 开头写明了数据来源等级（A/B/C）与抓取时刻（到分钟）
- [ ] 明确了热度口径，且 10 条用的是同一个口径
- [ ] 每条都有可点开的链接或截图来源
- [ ] 同一事件的多条词条已合并，并注明合并了哪几条
- [ ] 商业推广、广告位、争议话题已标注
- [ ] 摘要写的是"分布与阶段"，不是"都很火"
- [ ] 洞察每条都挂得住具体数据
- [ ] 没有把第三方榜说成官方榜

---

## 五、合规红线

- 不绕过登录、不抓取 App 接口、不采集个人主页与私信内容；
- 榜单只作趋势参考，**不作为"事实核查"结论**（热点里的医疗、理财、政策说法常常不准确）；
- 涉及品牌负面、争议人物、未成年人时，只描述"榜上出现了什么"，不做评价与扩散建议。
