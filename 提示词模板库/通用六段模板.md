# 提示词模板库 · T00 通用六段模板 v1.0

> 六段结构：身份角色 → 背景上下文 → 具体任务步骤 → 负面约束/正面示例 → 结构化格式 → 反向提问触发
> 用途：把口语化草稿升级为可直接投产的提示词，并自动提醒缺失信息。

---

## 一、怎么调用（给我看的部分）

| 项目 | 说明 |
| --- | --- |
| 触发口令 | 「套模板」「修饰提示词」「按模板改」「补全这个提示词」 |
| 你需要给 | ① 原始草稿（多粗糙都行）② 目标模型（可选）③ 用在什么场景（可选） |
| 我会输出 | ① **完整成稿**（六段齐全，可直接复制）② **缺口清单**（哪些段落是空的/含糊的）③ **反向提问**（最多 3 条，只问真正影响结果的关键项） |
| 我不会做 | 不替你编造业务数字、不虚构材料、不在信息不足时假装写完 |

## 二、模板正文（复制这段填空）

```text
# 一、身份角色
你是【角色】。你具备【专业能力/经验年限/方法论】，服务对象是【谁】。
你的判断标准是【最重要的 1-2 条价值观，如：先给结论、不堆砌术语】。

# 二、背景上下文
- 场景/业务：
- 已掌握的材料（附件/数据/历史结论）：
- 目标读者或使用者：，他们的关注点：
- 硬约束：时间 / 预算 / 工具 / 合规 / 不可动的前提
- 本次不涉及的范围：

# 三、具体任务步骤
1. 先做【拆解/核对/检索】，产出【中间物】
2. 再做【分析/写作/生成】，依据是【标准】
3. 最后做【自查/交叉验证】，检查【具体项】
交付物：【文件形式 + 内容要求 + 验收标准】

# 四、负面约束 / 正面示例
不要做：
- 不要【常见错误 1】
- 不要【常见错误 2】
必须做：
- 必须【关键动作】
正面示例（照这个质感写）：
> 【一段 3-5 行的样例】
反面示例（不要这样）：
> 【一段反例 + 一句说明为什么不行】

# 五、结构化格式
- 输出结构：【章节顺序 / 表格列名 / JSON 字段】
- 长度：【字数或篇幅】
- 语气：【正式/口语/简洁克制】
- 排版：【标题层级、是否用表格、代码块、单位与数字格式】

# 六、反向提问触发
遇到下列情况，先停下来提问，不要猜：
- 关键事实缺失（数字、对象、时间）
- 两种理解都说得通（歧义）
- 涉及不可逆操作（删除、发送、对外发布、花钱）
无法提问时，按【默认假设】继续，并在开头用「假设：」列出所有假设。
```

## 三、"该有的内容"检查表

| 段落 | 必须有 | 常见缺失（我会提醒你补） |
| --- | --- | --- |
| 身份角色 | 角色 + 能力来源 + 判断标准 | 只写"你是专家"，没写专在哪、按什么标准取舍 |
| 背景上下文 | 场景、材料、读者、硬约束 | 没交代读者是谁；没给材料却说"根据资料"；约束藏在心里 |
| 任务步骤 | 有序步骤 + 交付物 + 验收标准 | 只有一句"帮我写个方案"；没说做完什么样算合格 |
| 负面约束 | 3-5 条明确禁止项 + 正反示例 | 只写"要专业"；没有示例，模型只能自由发挥 |
| 结构化格式 | 结构 + 长度 + 语气 + 排版 | 没说多长；既想要报告又想要清单 |
| 反向提问 | 触发条件 + 默认假设规则 | 完全没写，导致模型在缺信息时胡编 |

## 四、每次修饰时我会先回你的缺口清单格式

```text
【缺口】第 X 段：缺少 ……（影响：会让我……）
【歧义】…… 有两种理解：A / B
【建议】补上这 3 项后，效果差别最大：1) 2) 3)
```

## 五、示例：一句话草稿 → 套模板后

**原始草稿**：帮我写个下季度部门工作规划。

**套模板后（节选）**：

- 身份角色：你是带过 20 人以上技术团队的业务负责人，习惯用"目标—抓手—风险"三段式思考，先给结论再给依据。
- 背景上下文：读者是公司管理层；本季度已完成【X】，团队 12 人，预算上限【Y】；硬约束：不新增编制。
- 任务步骤：1) 复盘本季度 3 项未达标指标 → 2) 提炼下季度 3 个目标并各配 2 个抓手 → 3) 自查每个目标是否有可量化验收口径。
- 负面约束：不要写口号式表述；不要出现无出处的行业数字；必须每个目标配一个可量化指标。
- 结构化格式：Markdown，四个二级标题，总长 800 字内，目标用表格（目标/抓手/指标/负责人/风险）。
- 反向提问：若"预算上限"和"本季度未达标指标"未提供，先提问，不要自行假定。
