# 提示词模板库

> 一个放"能直接用"的提示词模板的箱子：每个模板 = 六段骨架（身份 / 背景 / 步骤 / 约束 / 格式 / 反问）+ 该场景专用的口径与自检。
> 当前版本 **v1.1**（2026-10-20 建库，归档 6 个模板）。

---

| 编号 | 文件 | 解决什么 | 典型场景 | 触发口令 |
| --- | --- | --- | --- | --- |
| T00 | [通用六段模板.md](通用六段模板.md) | 把一句草稿补成可投产的提示词 | 任何提示词先"写全" | 「套模板」 |
| T01 | [语气-专业得体版.md](语气-专业得体版.md) | 专业谦和、去教育口吻、不留指摘点 | 邮件、汇报、回复质疑、催办 | 「按 T01 润色」 |

## 二、怎么选（先看这张表）

| 我要做的事 | 用哪个 | 补充 |
| --- | --- | --- |
| 有一句想法，想变成完整提示词 | T00 | 缺什么我会列清单问你 |
| 内容写好了，但怕语气不妥、被挑字眼 | T01 | 可单独用，也可接在 T00 后面 |
| 想快速掌握某主题最近发生了什么 | T02 | 必须先给时间窗和主题范围 |
| 同一件商品在几个平台哪个便宜 | T03 | 必须先锁定 SKU（容量/版本/颜色） |
| 这周干了什么，要交周报 | T04 | 素材在 `worklog/daily/` |

## 三、组合用法（顺序不能反）

| 组合 | 用途 | 顺序理由 |
| --- | --- | --- |
| T00 → T01 | 先补全内容，再调语气 | 先润色会把"信息缺失"藏进漂亮句子里 |
| T02 → T01 | 简报写完再润色，用于转发上级 | 事实先行，语气后调 |
| T04 → T01 | 周报成稿后过一遍指摘点自检 | 避免"待办写成完成"这类硬伤 |
| T02 → T03 | 先查政策与行情，再比价定预算 | 政策影响型号选择与合规成本 |

原则：**内容 → 事实 → 语气**。任何"先调语气"的做法，都会让缺口变得更难发现。

## 四、命名与版本规范

- 文件名：`类别前缀-名称.md`。基础类无前缀，语气类用 `语气-`，场景类用 `场景-`。
- 编号：`T00`–`T99`，唯一且不复用；新模板顺延编号，不插号。
- 版本：写在文件第 1 行标题末尾（如 `v1.0`）；**措辞调整 +0.1，结构调整 +1.0**。
- 修订：在该文件末尾「维护」段追加一行「vX.Y：改了什么」，不删旧记录。

## 五、调用约定（我这边怎么执行）

1. 你说口令 + 给素材，我按对应模板出稿；
2. 每次交付固定三段：**成稿**（可直接复制）→ **缺口清单**（缺哪段、影响什么）→ **反向提问**（≤3 条，只问关键项）；
3. 拿不到的数据一律标【未获取】或【待补充】，**不编数字、不编来源、不编价格**；
4. 涉及对外发送、删除、花钱的动作，先确认再执行。

## 六、通用缺口登记（跨模板反复出现的问题）

| 反复缺的东西 | 导致的结果 | 补法 |
| --- | --- | --- |
| 受众与提交要求 | 结构、详略、语言全错，需要返工 | 说明"给谁看 + 有没有固定模板 + 字数" |
| 时间窗 | 检索类把旧闻当新闻 | 给明确起止日期 |
| 素材出处 | 结论无法核验 | 给文件路径或链接 |
| 脱敏红线 | 客户名、IP、内部系统名外泄 | 提前说明哪些不能出现 |
| 口径（工时/价格/SKU） | 数字对不上，被追问 | 明确统计口径与计算方式 |
