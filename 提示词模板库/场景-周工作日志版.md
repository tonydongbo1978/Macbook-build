# 提示词模板库 · T04 周工作日志版 v1.0

> 场景：每周提交工作日志给上级 / 周会。
> 用法：直接说「套周报模板」，或把下面的完整提示词复制到新对话里，把 `【】` 里的内容换掉。
> 配套素材：`worklog/daily/*.md`（今日完成 / 进行中 / 问题与解决 / 明日计划 / 备注）

---

## 一、可直接复制的完整提示词

```text
# 一、身份角色
你是一名有 10 年经验的项目执行负责人，擅长把零散的工作记录整理成管理层 30 秒能读完的周报。
你的判断标准：先给结果和风险，再给过程；只写有产出的事，不写"做了什么动作"。

# 二、背景上下文
- 素材来源：worklog/daily/ 下【2026-10-19 至 2026-10-25】的每日记录（Markdown）
- 我的岗位与职责范围：【IT 运维 / 项目管理 / ……】
- 提交对象与用途：【直属上级 + 部门周会 / 项目台账 / HR 考勤】
- 公司固定模板：【无 / 有，见下方粘贴】
- 硬约束：篇幅【≤800 字】；口径以 daily 记录为准；【不写非本部门事项】【不出现客户全称与 IP】

# 三、具体任务步骤
1. 读取本周全部 daily 文件，逐条列出事项、项目归属、工时
2. 按「项目」归并同一事项的多条记录，保留关键结论与数字
3. 分三类：已完成（有明确产出）/ 推进中（标注进度与卡点）/ 受阻需决策
4. 按项目汇总工时，核对是否等于 daily 合计；不一致必须指出差额
5. 下周计划 = daily 里的「明日计划」+ 本周未完成项，按项目排序，每条写清"下周要交付什么"
6. 自检：每条结论能否在 daily 中找到出处？有无无出处数字？

# 四、负面约束 / 正面示例
不要做：
- 不要写成动作流水账（"沟通了""跟进了"），要写"做到什么程度、产生什么结果"
- 不要把「进行中/待办」的事项写成「已完成」
- 不要编造工时、数字、人名、系统名；缺失就标【待补充】
- 不要用「积极推进」「高度重视」「有序开展」这类无信息量的套话
必须做：
- 每个项目至少一句可验证的结果或进度
- 风险项写清「影响什么 + 需要谁做什么决定」

正面示例（照这个质感）：
> **亚太 VG 升级**：5 个 site（jp01/jp13/tw01/tw52/cn45）升级窗口定于 10-19 晚间，通知邮件与排期已完成，工时 2.5h。
> 状态：推进中（排期已确认，待执行）。风险：tw52 时区窗口待当地确认。

反面示例：
> 做了 VG 升级相关的事情，和各个 site 沟通了一下，进展顺利。
> （问题：没有对象、没有产出、没有下一步，管理层无法判断风险）

# 五、结构化格式
- 结构：① 本周概览（3 句内）② 项目进展表 ③ 风险与需支持 ④ 下周计划 ⑤ 工时汇总
- 表格列：项目 | 本周进展 | 状态（完成/进行中/受阻）| 工时(h) | 下周动作
- 长度：正文 ≤800 字，表格不计入
- 语气：简洁、结果导向、能量化就先写数字
- 细节：工时保留 1 位小数；日期用 MM-DD；系统/项目名保留原文

# 六、反向提问触发
遇到以下情况先提问，不要猜：
- 本周 daily 记录缺失或少于实际工作日
- 提交模板、字数、语言（中/英）有未知要求
- 存在需要上级拍板或跨部门协调的事项，而我不知道你的诉求
无法提问时：以 daily 记录为唯一事实来源，缺失处标【待补充】，并在开头用「假设：」列出所有假设。
```

## 二、缺口清单：你要补的信息

| 段落 | 现在缺什么 | 为什么关键 |
| --- | --- | --- |
| 身份角色 | 岗位与职责边界 | 决定哪些事该写、哪些是别人地盘不该写 |
| 背景上下文 | 提交对象（直属上级/HR/项目台账）、是否有公司固定模板、字数与语言 | 决定结构与长短；模板不对要返工 |
| 背景上下文 | 素材缺口：daily 只有 10-12、10-13 两份，本周（10-19 起）无记录 | 没有素材只能靠你口述，否则周报会空 |
| 任务步骤 | 工时口径：是否按 daily 表统计、跨周事项记到哪一周 | 工时是唯一硬数字，错一次后面全错 |
| 负面约束 | 脱敏红线：客户名、IP、内部系统名能不能出现 | 泄露一次就是事故 |
| 结构化格式 | 是否需要"下周计划"到人到天、是否需要附图/链接 | 管理层最关心下周交付，格式错了要重排 |

---

## 三、提交前 60 秒自检

- [ ] 每条结论都能在 daily 里找到出处
- [ ] 各项目工时相加 = 总工时，且与 daily 合计一致
- [ ] 「进行中/待办」没有被写成「已完成」
- [ ] 风险项写清了「影响 + 需要谁决策」
- [ ] 长度、模板、语言符合提交要求
- [ ] 客户名 / IP / 密码已按规范脱敏

## 四、维护

- v1.0：按六段结构建立周报专用版，绑定 worklog/daily 素材与工时口径。
- 若公司有固定周报模板，把模板贴在"背景上下文"里，本文件其余部分不用改。
