# 定时任务说明（launchd）

每日 **07:00** 自动生成当天的时事速递草稿。

---

## 文件清单

| 文件 | 作用 |
|---|---|
| `~/Library/LaunchAgents/com.local.kb-digest.plist` | launchd 任务定义 |
| `知识库/scripts/daily_digest.sh` | 包装脚本（路径处理 + 日志） |
| `知识库/scripts/new_digest.py` | 实际生成日报 |
| `知识库/scripts/logs/digest.log` | 正常输出日志 |
| `知识库/scripts/logs/digest.error.log` | 错误日志 |

---

## 常用命令

```bash
# 查看任务状态
launchctl print gui/$(id -u)/com.local.kb-digest

# 立即手动触发一次（测试用）
launchctl kickstart -p gui/$(id -u)/com.local.kb-digest

# 暂停 / 恢复
launchctl bootout gui/$(id -u)/com.local.kb-digest
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.local.kb-digest.plist

# 直接运行（不经 launchd，最可靠的手动方式）
bash 知识库/scripts/daily_digest.sh
```

## ⚠️ 已知限制：需要授权才能实际跑通

任务已成功注册（`launchctl print` 可见，`Hour 7 / Minute 0` 已生效），但**在当前 DSH 沙箱环境下实际执行会失败**：

```
runs = 2
last exit code = 126
```

错误日志内容：

```
shell-init: error retrieving current directory: getcwd: cannot access parent directories: Operation not permitted
/bin/bash: .../daily_digest.sh: Operation not permitted
```

**原因**：DSH 的文件沙箱会限制由本会话派生的进程访问工作区外的路径。已用对照实验确认 —— 一个放在 `/tmp`、不含任何中文路径的极简任务同样 `bootstrap` 失败（`Input/output error`），说明问题出在沙箱而非 plist 配置。

**结论**：定时机制本身是正确的、已注册的；要在真实环境下生效，需满足其一：

1. 在**普通终端**（非 DSH 沙箱）中执行一次重新加载：
   ```bash
   launchctl bootout gui/$(id -u)/com.local.kb-digest 2>/dev/null
   launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.local.kb-digest.plist
   ```
2. 或者确认 DSH 以更高权限模式运行时再触发。

在限制解除前，**手动执行 `bash 知识库/scripts/daily_digest.sh` 完全正常**（已验证）。

## 踩坑记录

配置过程中遇到的两个真实问题，供日后排查参考：

1. **plist 权限必须是 644**。用 `write` 工具创建的 plist 默认是 `600`，`launchctl bootstrap` 会静默失败并报 `Input/output error`（错误码 5），日志里看不出真实原因。**`chmod 644` 后立刻成功**。

2. **shell 脚本必须有读权限**。`chmod +x` 得到的 `-rwx--x--x` 不够 —— launchd 用 `bash <script>` 方式调用时需要读取脚本内容，必须是 `755`（`-rwxr-xr-x`）。

3. **`launchctl load` 已过时**。新系统请用 `launchctl bootstrap gui/$(id -u) <plist>`，报错信息更明确。

## 设计说明

- **`RunAtLoad` 设为 `false`**：这是每日一次性任务，不是常驻服务。开机时不必立即跑一次。
- **`StartCalendarInterval` 而非 `StartInterval`**：固定在 07:00，而不是"每隔 24 小时"。机器休眠错过时间点，唤醒后 launchd 会补跑一次。
- **不加 `KeepAlive`**：任务执行完即退出，不需要守护。
- **包装脚本经 `new_digest.py` 的幂等保护**：即使重复触发或补跑，也不会覆盖已填写的内容。
- **日志自动截断**：超过 1MB 时保留最后 500 行，避免无限增长。
