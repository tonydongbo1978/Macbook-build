# 模式库（可操作的写法）

## 1. 五级能力选型
**何时用**：不确定该用提示词、工具、MCP、智能体还是 Skill。
**怎么做**：一次性→提示词；要实时/操作→工具；多服务→MCP；多步自主→智能体；专业+稳定+重复→Skill。
**权衡**：越往后成本与治理要求越高；简单任务上 Skill 是负优化。

## 2. 单一职责拆分
**何时用**：一个 Skill 想覆盖多种任务。
**怎么做**：按"一个核心动作"拆（周报/纪要/邮件/公告各一个）；用 description 划清边界。
**权衡**：拆得越细，编排越多；但可维护性与触发准确率显著提升。

## 3. 元数据写法
**何时用**：任何新 Skill。
**怎么做**：name 小写连字符；description 第三人称，写清"输入—输出—何时触发"，中文可用。
**权衡**：description 越长越准，但占用索引上下文；控制在 2–3 句。

## 4. 五标准自检
**何时用**：Skill 写完、上线前。
**怎么做**：逐项打钩——元数据准、边界清、输入输出明、步骤可执行、失败处理全。
**权衡**：五项都做的 Skill 更长；但缺任何一项都会在真实任务中暴露。

## 5. 工作流 + 清单 + 闭环
**何时用**：多步骤、要求完整的任务。
**怎么做**：写清阶段顺序；执行中维护检查清单；关键节点"验证→修正→继续"；交付前逐条自检。
**权衡**：增加轮次与 token；但能显著降低"漏要求"。

## 6. 评估驱动迭代
**何时用**：想提升 Skill 质量但不知从哪改。
**怎么做**：裸跑→记录失败→写成需求清单→先写考题→做最小版→每次改动回归全部考题。
**权衡**：前期慢；但能避免"越改越乱"。

## 7. 三级约束混用
**何时用**：设计一个完整流程。
**怎么做**：计算用脚本、结构用模板、判断用策略；按"10 人测试"决定每一段。
**权衡**：混用增加设计复杂度；但单一级别必然在某些环节出错。

## 8. 知识库工程
**何时用**：Skill 需要私有知识。
**怎么做**：全部转纯文本；按业务结构建目录；文件名写全；加 `索引.md`；引用写到文件级；粒度用"5 文件法则"检验。
**权衡**：整理成本前置；但不整理会让每次执行都变慢变贵。

## 9. 上下文减负
**何时用**：批量文件、长文档、多轮任务。
**怎么做**：脚本算完只输出结论；脚本内调 API 做批量预处理；子智能体隔离中间过程。
**权衡**：脚本带来费用与维护；但比上下文爆掉重跑便宜。

## 10. 对话萃取隐性知识
**何时用**：专家"会做但写不出来"。
**怎么做**：AI 扮新人追问（为什么/如果/依据）→ 讲真实案例 → 归纳规则 → 新案例验证 → 转 SKILL.md。
**权衡**：耗时 1–2 小时/技能；但这是唯一能拿到"判断依据"的方法。

## 11. 技能编排
**何时用**：复杂任务需多个能力。
**怎么做**：输入输出标准化；各自可独立使用；在 SKILL.md 声明可协作对象与输出格式。
**权衡**：编排降低单点复杂度，但增加调用链与失败点。

## 12. 库治理分级
**何时用**：Skill 数量增长。
**怎么做**：个人＝分类/索引/备份；团队＝权威来源/负责人/索引文档/季度审查；版本用 Git。
**权衡**：治理有开销；没有治理则重复造轮子与版本混乱。
