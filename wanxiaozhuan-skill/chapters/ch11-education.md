# 第 11 章：教育与生活案例

## 核心思想
教育类 Skill 的共同点是**知识密度高、结构要求强、容错率低**：讲解要可视化、试卷要符合大纲、翻译要术语一致。它们最依赖 references（知识库）与脚本（渲染/校验），而不是提示词技巧。

## 本章框架

- **11.1 可视化教学讲解**
  - 链路：知识点拆解（策略）→ 讲解脚本/分镜（模板）→ 图表/动画渲染（脚本或绘图工具）→ 输出课件。
  - 关键：先定"认知路径"（从具体到抽象，或从问题到原理），再定表现形式；否则只是"把文字配上图"。
- **11.2 试卷生成**
  - 三段：大纲/考点对齐（references 中的考纲与知识点表）→ 题目生成（策略指引 + 难度分布约束）→ 排版输出（脚本/模板）。
  - 关键：**难度与题型分布必须显式约束**（如 基础 60%/中档 30%/拔高 10%），并做"答案一致性自检"。
- **11.3 长文专业翻译**
  - 链路：术语表（references，强制一致）→ 分段翻译（脚本切片，避免上下文溢出）→ 一致性校验（脚本比对术语）→ 增量翻译（只译新增/修改段落）。
  - 关键：**术语表 + 增量翻译**是专业翻译与"机翻"的分水岭；前者保证一致性，后者降低成本并保持版本间表述统一。
- **三条通用规律**：
  1. 教育/专业场景，**知识库质量 > 提示词质量**；
  2. 凡是"有标准答案"的环节，都要加**自动校验**（答案核对、术语比对、难度统计）；
  3. 长文档场景，**切片 + 增量**是唯一可扩展的做法。

## 关键概念
- **认知路径**：讲解的顺序设计（具体→抽象 / 案例→原理）。
- **难度分布约束**：用比例控制题目结构。
- **术语表（Glossary）**：翻译一致性的锚。
- **增量翻译**：只处理变更部分，保持版本一致。

## 心智模型
- **"讲解的本质是降低认知负荷"**：不是加更多信息，而是排好顺序。
- **"有答案的环节就能自动校验"**：这是教育类 Skill 可靠性的来源。
- **"长文不是一次读完，而是切片处理"**：脚本切片 + 术语表 + 汇总。

## 反模式
- 让模型"自由发挥"出题（难度失控、考点偏移）。
- 整本长文一次塞进上下文（必然截断或漂移）。
- 没有术语表就做专业翻译（同一术语多种译法）。

## 关键结论
1. 教育类 Skill 的门槛在"知识结构化"，不在生成能力。
2. 校验环节（答案、术语、难度）决定了它能不能被真正使用。
3. 增量与切片是处理长文档的通用工程手法。
