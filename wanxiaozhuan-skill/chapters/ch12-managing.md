# 第 12 章：管理你的数字员工团队

## 核心思想
Skill 一多，问题就从"怎么写"变成"怎么管"：找不到、改坏了、传不出去、泄密。管理强度要**匹配规模**——一个人别搞企业级流程，几十个人则必须有权威来源、负责人和审查机制。

## 本章框架

- **个人/小团队：三件事**
  1. **分类存放**：按用途分目录（工作类/内容类/生活类），文件夹与 Skill 名带关键字；
  2. **索引清单**：一个文本文件，列出每个 Skill 的名称、用途、何时用、上次更新时间——**让 AI 扫目录自动生成**，每次增改后更新；
  3. **备份习惯**：整个 Skill 目录同步网盘（坚果云/百度网盘/OneDrive）。
  - 原则：管理方式匹配规模，一个人的时候别上重流程。
- **团队/组织：四件事**
  1. **统一存放**：一个"权威来源"（Git 仓库或共享目录），禁止各自保存版本；可加"组织级"层（项目级 > 全局级 > 组织级）；
  2. **指定负责人**：谁创建谁负责，或按业务域归属（财务/法务）；职责＝收反馈、定期更新、答疑；
  3. **索引文档**：比个人版更详细（用途、用法、维护者、更新时间），新人入职看一遍就知道有哪些"数字员工"；
  4. **定期审查**：每季度检查——哪些还在用、哪些过时、哪些重复可合并；按使用频率与节省工时分配维护资源。
  - Anthropic 的同类建议：记录业务目的、指定维护者、做新人引导、统一命名规范。
- **版本管理（Git）**
  - 好处：变更可追溯、可回滚、多人协作、可评审（Pull Request）。
  - 做法：Skill 目录即仓库内容；提交信息写清"改了什么、为什么"；重要 Skill 用分支 + 评审。
- **分享与权限**
  - 公开分享：`.skill` 压缩包 / GitHub / Skill 市场；发布前做安全审查（去密钥、去敏感信息）。
  - 内部共享：放在团队权威目录，配合权限控制；**含内部数据的 Skill 不应随意复制外流**。
  - 风险意识：Skill 是可执行能力的载体，分享 = 交出部分权限。
- **Skill 库 = 组织知识资产**
  - 老员工离职，经验留在 Skill 里；新人加载即上手。
  - 这就是把 5.3 的"隐性知识萃取"从个人行为升级为组织能力。

## 关键概念
- **权威来源**：唯一的可信分发点。
- **Skill 负责人**：类比的代码 Owner。
- **季度审查**：淘汰、合并、更新。
- **知识资产化**：Skill 库作为企业可计价的能力存量。

## 心智模型
- **"Skill 库像代码库"**：需要版本、评审、Owner、废弃流程。
- **"索引比搜索重要"**：几十个 Skill 时，一份清单胜过任何工具。
- **"管理成本要低于复用收益"**：过度治理会让人不愿贡献。

## 反模式
- 每个人本地各存一份（版本混乱、重复造轮子）。
- 无 Owner（没人更新，半年后失效）。
- 直接把含客户数据/密钥的 Skill 发到公开群。
- 只建不管（越积越多，最终没人用）。

## 关键结论
1. 治理强度随规模升级：个人三件事、团队四件事。
2. 版本控制 + 负责人 + 定期审查，是 Skill 库长期可用的三根支柱。
3. 组织的竞争力来自"把隐性知识变成可分发的 Skill"，而不是拥有多少提示词。
