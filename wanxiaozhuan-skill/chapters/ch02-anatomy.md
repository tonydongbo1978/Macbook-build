# 第 2 章：初识 Skill

## 核心思想
Skill 不是软件、不是服务，**就是一个文件夹**：一个必需的 `SKILL.md`，加上三个可选目录 `references/`、`scripts/`、`assets/`。极简的载体 + 严格的约定，换来跨平台可移植与可审计。

## 本章框架

- **最小 Skill**：`<skill-name>/SKILL.md`，仅此一个文件即可工作。
- **四个组成部分（岗位类比）**：
  | 部分 | 作用 | 类比 |
  |---|---|---|
  | SKILL.md | 指令、流程、边界 | 岗位说明书 |
  | references/ | 供"阅读理解"的资料 | 教材/知识库 |
  | scripts/ | 供"执行"的代码 | 计算器/工具箱 |
  | assets/ | 供"直接使用"的模板素材 | 文具柜/素材库 |
  - 关键区分：references 要**看懂**，assets 只要**拿来用**（Logo、Word 模板、CSS）。
- **SKILL.md 结构**：
  - **元数据区**（`---` 包裹的 YAML）：必填 `name`（英文小写+连字符，**不能用中文**）、`description`（**可用中文**，是 AI 判断何时调用的唯一依据）；可选 `license`、`compatibility`、`metadata`（author/version 等，缩进两格）。
  - **正文区**（Markdown）：建议含「使用场景 / 工作流程 / 输出格式 / 语言风格 / 注意事项」五个二级标题。
- **好的 SKILL.md 四特点**：描述精准、流程清晰、边界明确、格式规范。
- **文件引用规则**：
  - 相对路径以 **SKILL.md 所在目录**为基准（写 `scripts/x.py`，不写 `./scripts/x.py`）；
  - 统一用正斜杠；路径**区分大小写**（全小写最稳）；避免空格与特殊字符；
  - **不引用 Skill 目录之外的文件**（保持自包含、可移植）；确需外部文件时，让智能体运行时向用户要路径。
- **两种存在形式**：文件夹（开发/迭代/Git 协作）与 `.skill`（本质是 zip，用于分发；`skill-creator` 可打包并校验）。
- **存放两级与优先级**：项目级（仅当前项目）> 全局级（所有项目）；同名时项目级优先。
  - 发现机制：扫描目录 → 读 SKILL.md → 解析 name/description → 建索引。
- **渐进式披露（核心机制）**：
  1. **元数据层**：启动时只加载 name+description，几十个 Skill 也只占极小上下文；
  2. **指令层**：判定要用时加载 SKILL.md 全文（自包含，能独立完成常规任务）；
  3. **资源层**：按需读 references / 调 scripts / 用 assets，任务结束即释放。
  - 价值：可以同时拥有几十种专业能力，却不拖累推理质量；资源层可承载海量知识而不影响加载性能。
- **OpenSkills 标准**：
  - 元数据规范如上；正文建议 **≤500 行、≤5000 tokens**（中文约 7500–10000 字），超出部分拆到 references；
  - 官方校验工具 `skills-ref`（`skills-ref validate ./my-skill`、`skills-ref init`、`skills-ref list`）；
  - 已在 Cursor、Claude Code、OpenCode、TRAE、扣子、OpenClaw、Codex 等落地。

## 关键概念
- **渐进式披露**：元数据 → 正文 → 资源，三级按需加载。
- **自包含**：SKILL.md 正文应能独立指导常规任务，只在深入细节时才引用外部文件。
- **项目级 / 全局级**：作用域不同的两个存放层。
- **.skill**：带校验的 zip 分发格式。

## 心智模型
- **"文件夹即产品"**：Skill 的竞争力在内容，不在格式；载体越简单，越容易复用与审计。
- **"description 是漏斗口"**：写不好 description，Skill 永远不会被触发——这是最高杠杆的一行字。
- **"正文是给模型的军令，不是给人的说明书"**：解释性文字是噪声。

## 反模式
- 把全部知识塞进 SKILL.md（超长、拖慢、挤压其他 Skill）。
- description 写成"这是一个很实用的工具"（无法判断何时调用）。
- 用中文 name、含空格路径、跨目录 `../` 引用（可移植性崩坏）。
- 把 Word/PDF 直接丢进 references（每次都要解析，成本与延迟上升）。

## 关键结论
1. 一个 Skill 的质量，80% 由 description + 工作流程决定。
2. 三级披露决定了"知识可以很多，但上下文只加载需要的部分"。
3. 自包含 + 相对路径 + 纯文本，是可移植与可维护的三条铁律。
