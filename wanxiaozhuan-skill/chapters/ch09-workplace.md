# 第 9 章：职场与工作案例

## 核心思想
七个职场 Skill 共享同一套施工流程：**拆分任务 → 逐环节选约束级别 → 把规则外置到 references → 封装 → 处理上下文与边界**。看懂这套模板，比记住七个案例更有用。

## 本章框架

- **通用施工流程（5 步）**：
  1. **拆分任务**：把需求拆成"读取/理解/判断/输出"几段；
  2. **选策略**：确定性环节→脚本；判断环节→策略指引；格式环节→模板；
  3. **外置规则**：筛选规则、格式规范等放 references（换岗位只换规则文件）；
  4. **封装 SKILL.md**：写清触发条件、流程、输入输出、失败处理；
  5. **应对规模**：量大时用脚本预处理或子智能体控上下文。
- **七个案例的要点**：
  - **9.1 简历筛选专家**：三档分类（淘汰/待人工审查/直接面试）；规则分层＝硬性条件一刀切 + 加分项量化 + 减分项风险提示；**边界案例必须标出交人工**（如差 2 个月满 3 年）；两三百份时用 `pre_screen.py` 批量调 API 预处理。
  - **9.2 公司公文撰写**：两阶段设计——**学习阶段**（解析标准模板的字体/字号/行距/页眉页脚/Logo，产出 `format_spec.md` + 渲染脚本）与**使用阶段**（Markdown 内容 → 脚本渲染成规范 Word）；格式规范与图片资源分别落到 references/ 与 assets/。
  - **9.3 可视化图表制作**：数据→图表类型选择→样式规范；图表参数与配色模板化。
  - **9.5 数据分析与自动报告**：脚本算指标（精确、省上下文）→ 模板定报告结构 → 策略指引写结论与建议。
  - **9.6 客户跟进**：把销冠的跟进节奏与话术固化为流程；按客户阶段触发不同动作。
  - **9.7 招标文件解析**：长文档切分 + 关键条款抽取 + 合规点核对；强调"先定位再精读"。
  - （9.4 为会议纪要类场景，同为"读取→提炼→模板输出"结构。）
- **贯穿的技巧标签**：策略指引 / 模板框架 / 程序脚本 / references 知识库 / 闭环反馈 / 上下文优化 / Skill 协作。

## 关键概念
- **三档分类**：把判断结果分成"确定淘汰/确定通过/需人工"，把不确定性显式暴露。
- **两阶段 Skill**：学习阶段产出规范与脚本，使用阶段反复执行。
- **规则外置**：规则与指令分离，多岗位复用同一 Skill。
- **批量预处理**：脚本+API 把 N 份文件压成 N 行结论。

## 心智模型
- **"先分类，再自动化"**：分类标准不清，自动化只会放大混乱。
- **"格式归脚本，判断归模型，结构归模板"**：三分法可套用到几乎所有职场 Skill。
- **"边界案例是人类的价值所在"**：不要追求 100% 自动判定。

## 反模式
- 让模型直接读几百份文件（上下文必爆）。
- 把筛选规则写进 SKILL.md（换岗位就要改 Skill）。
- 对模糊案例强行给结论（HR 无法复核、责任不清）。

## 关键结论
1. 职场 Skill 的收益主要来自"高频 + 规则明确 + 输出格式固定"的环节。
2. 规则外置 + 三档分类，是可维护性与可信度的关键。
3. 规模问题不是模型问题，是上下文工程问题。
